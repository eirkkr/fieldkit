# Merge a pull request

Reaching this skill means merging is approved for one head: user typed `/merge`, or caller asked and got a yes. That head is the SHA the caller named, else `git rev-parse HEAD` now, expanded with `git rev-parse <sha>^{commit}`: the approved sha. Any push adding or rewriting a commit, or a moved head (step 2), voids the approval: push a fix only where a step says to, then stop, report what changed, ask again. After the new yes, the new head is the approved sha; carry on from step 2 (a fresh `/merge` starts at step 1). Sole exception: this PR's gate approval commits, listed in `skills/change-stage/GATE.md` (the decision record, the **Reviewed at** line and the tick; not a fix the reviewer asked for): the head they leave is the approved sha. In this turn:

1. **Get a PR open.** No open PR for this branch: follow `skills/pr/SKILL.md` first.
2. **Check it can merge:** `gh pr view --json number,title,state,mergeable,reviewDecision,statusCheckRollup,baseRefName,headRefName,headRefOid,url`. Not open or has conflicts: stop, report what blocks it. Then review state, from `reviewDecision`: `APPROVED`, or empty (no review required), carries on. `REVIEW_REQUIRED` or `CHANGES_REQUESTED`: report the PR needs a review on GitHub; go on to step 7 only if the user says their own account can bypass the rule (GitHub refuses the merge if not). Never add `--admin` or change the ruleset. After `git fetch`, a `headRefOid` that is not an ancestor of the approved sha (`git merge-base --is-ancestor <headRefOid> <approved sha>` fails) means the head moved: stop as above. One behind it is fine; step 6 pushes the difference. Checks still running are waited out in step 5.
3. **Rewrite claims the merge falsifies.** Run `git grep -n -e '#<N>' -e 'pull/<N>' -e '<branch>'`. A sentence calling the PR or branch open, unmerged or in review turns false at the merge: rewrite on the branch and push. Then stop and ask again, as above.
4. **Draft the squash subject and body**, summarising the whole change, not concatenating commits. Start from context in hand plus `git log <base>..<branch>`; read `git diff <base>...<branch>` only if those leave the picture unclear.
   - Message follows `conventions/git.md`'s Commits rules, `(#<PR>)` ending the subject and counting toward its 72. A `!` title's `BREAKING CHANGE:` line comes over from the PR body. The kit's merge-message hook refuses a merge breaking these, saying what to fix.
   - `Closes #X` lines: read `conventions/git.md`'s Squash-merge rule first. It names the two sources a number may come from and the check that it is an issue. No number: no such line.
   - Credit lines: `conventions/git.md`'s Squash credit rule.
5. **Wait for running checks:** `gh pr checks --watch --fail-fast --interval 15`, Bash timeout up to the 600000ms maximum. Merge only once every check has finished and passed. One fails: stop, report which (a fix is a new commit: ask again as above). Wait times out: report CI still running; `/merge` can run again later. Then, if `grep -l 'github.run_attempt > 1' .github/workflows/*.yml 2>/dev/null` prints a file (no output means no Manual CI), the repo's CI is skipped until re-run (`conventions/ci.md`, "Manual CI") and `--watch` returns on a `skipping` check: read `gh pr checks` again; any `skipping`: stop, report CI has not run. Start it as the repo's docs say, then run `/merge` again.
6. **Push** only up to the approved sha, if the remote lacks commits up to it: `git push origin <approved sha>:refs/heads/<headRefName>`. Local HEAD ahead of the approved sha: stop as above.
7. **Merge:** `gh pr merge <PR> --squash --match-head-commit=<approved sha>` with the drafted subject and body; body via `--body-file -` and heredoc, keeping line breaks. GitHub refuses the merge if the head has moved: stop as above. Write the flag with `=`; with a space, the merge-message hook reads an all-digit SHA as the PR number.
8. **Clean up locally.** Remove only the worktree this `/merge` ran in, and its branch. Which case applies:
   - Session in a worktree it created with `EnterWorktree`: `git status --porcelain` there. Output: keep it, note the files. Clean: `ExitWorktree` `remove` with `discard_changes: true` (only the merged commits remain; this `/merge` is the ask).
   - Checkout you are in is any other linked worktree (`git rev-parse --git-dir` differs from `--git-common-dir`: resumed session, entered by `path`, `claude --worktree`). Keep it, noting the reason, when `git worktree list --porcelain` shows it `locked` (Claude Code locks the worktree of a live `claude --worktree` session; never unlock it), when `git status --porcelain` prints anything, or when `git rev-parse HEAD` is not the approved sha. Otherwise remove it:
     1. Save its path and branch, then `cd` to the main checkout (the first line of `git worktree list --porcelain`): `git worktree remove` succeeds with the shell inside the tree and leaves the shell in a deleted directory.
     2. `git worktree remove <path>`. If that refuses only because of initialised submodules (the clean check already passed), repeat it once with a single `--force`, never two.
     3. `git branch -D <branch>` (plain `-d` doesn't recognise a squash merge), then `git worktree prune`.
   - Main checkout, with the branch checked out in another linked worktree: that worktree is not the one this `/merge` ran in. Keep it and the branch, noting the path and that it was not the worktree this `/merge` ran in.
   - Main checkout, branch in no linked worktree: on the merged branch, switch to the default branch (`gh repo view --json defaultBranchRef -q .defaultBranchRef.name`); on any other branch, stay. `git branch -D <branch>` if `git branch --list <branch>` prints it.
   - Last, in the checkout you are in (the main checkout, if you removed a worktree): `git pull --prune` on the default branch, else `git fetch --prune`.
9. **Report** PR number and URL, and that it merged, or what still blocks it. Then the cleanup: each removal (worktree path and branch), each worktree or branch kept with its path and the reason, and, when a worktree was removed, that its git-ignored files went with it.
